Category One

Software Engineering and Design

Orelia Wellness Clinic Management Software

Orelia is a full stack clinic management application I independently developed for a local wellness clinic to transition its manual record-keeping processes to a centralized digital system.

The application supports patient management, inventory management, injection tracking with automated inventory deductions, payments, laboratory records, treatments, and other clinic operations.

For my Software Engineering and Design enhancement, I refactored the original monolithic FastAPI backend into a modular architecture with dedicated configuration, database, model, router, service, and error-handling components.

Enhancement Highlights

  • Refactored a monolithic backend into a modular software architecture
  • Created dedicated Pydantic models and domain-specific FastAPI routers
  • Introduced service layers for patient, injection, and inventory operations
  • Centralized PostgreSQL database access and application configuration
  • Strengthened input validation for inventory and injection data
  • Implemented centralized exception handling and safer client responses
  • Standardized HTTP status handling for expected application errors
  • Removed development/debugging code and unnecessary configuration exposure
  • Improved maintainability, scalability, testability, and separation of concerns

Category Two: Algorithms and Data Structures

First Expired, First Out (FEFO) Inventory Allocation

For the Algorithms and Data Structures enhancement, I improved the inventory management process within the Orelia Clinic Management Software by implementing a First Expired, First Out (FEFO) allocation algorithm. The enhancement automatically prioritizes eligible medication inventory based on expiration date, helping ensure that inventory expiring soonest is used before newer inventory.

The algorithm retrieves eligible, non-expired inventory lots in expiration-date order and performs a linear traversal to determine how the required medication quantity should be allocated. When a single lot cannot satisfy the requested amount, the algorithm continues across multiple lots until the required quantity has been fulfilled. A new relational allocation structure also preserves the exact inventory lots and quantities associated with each injection.

Enhancement Highlights

  • Implemented FEFO inventory allocation based on medication expiration dates
  • Added expiration-date tracking to inventory records
  • Added linear traversal of ordered inventory lots to fulfill medication requirements
  • Supports allocation across multiple inventory lots
  • Records exact lot-by-lot inventory usage for each injection
  • Added transactional inventory deductions and restoration
  • Updated injection creation, modification, and deletion to support FEFO allocations
  • Preserved backward compatibility with injection records created before the enhancement
  • Added insufficient-inventory handling with 409 Conflict responses
  • Prevents partial inventory deductions when an allocation cannot be fulfilled
  • Improved data integrity and traceability through a one-to-many injection-to-allocation relationship

This enhancement demonstrates the use of algorithmic principles to solve a practical inventory-management problem while improving the reliability, traceability, and scalability of the original application.

Category Three

Databases

Database Performance, Integrity, and Scalability

For the Databases enhancement, I improved the PostgreSQL database used by the Orelia Clinic Management Software by focusing on query performance, data integrity, and scalability. The enhancements were based on the application's existing database operations and the ways clinic data is retrieved and maintained.

Targeted database indexes were added to support FEFO inventory queries, chronological injection-history retrieval, and inventory allocation lookups. I also added a database-level constraint to prevent negative inventory quantities and implemented pagination for injection history so the application can retrieve manageable portions of data as the number of records grows.

Enhancement Highlights

  • Added a composite index on medication name and expiration date to support FEFO inventory queries
  • Added an index to support chronological injection-history retrieval
  • Added an index for efficient injection inventory-allocation lookups
  • Added a database-level constraint preventing negative inventory quantities
  • Validated the inventory constraint by confirming PostgreSQL rejects invalid negative quantities
  • Added LIMIT and OFFSET pagination to injection-history retrieval
  • Exposed pagination controls through the FastAPI endpoint
  • Improved database performance, integrity, reliability, and scalability

This enhancement demonstrates how database design decisions can improve the overall reliability and scalability of an application. Rather than changing the database unnecessarily, the enhancements target actual query patterns and data-integrity requirements within the clinic management system.
